<task type="auto">
  <name>Task 1: Add Caddy reverse proxy and restrict Superset port exposure</name>
  <files>docker/Caddyfile, docker-compose.yml</files>
  <action>
    **Create `docker/Caddyfile`** with the following content:

    ```
    # For local/internal deployment: self-signed TLS
    # Replace {:443} with your domain (e.g., superset.example.com) for public deployment
    # and remove "tls internal" to use automatic Let's Encrypt certificates.

    {:443} {
        tls internal

        reverse_proxy superset:8088

        # Security headers (supplement Talisman)
        header {
            X-Content-Type-Options "nosniff"
            X-Frame-Options "DENY"
            Referrer-Policy "strict-origin-when-cross-origin"
        }
    }

    # HTTP to HTTPS redirect
    {:80} {
        redir https://{host}{uri} permanent
    }
    ```

    **Modify `docker-compose.yml`:**

    1. Add a `caddy` service block BEFORE the superset service (after redis, before superset-init):

    ```yaml
      # ---------------------------------------------------------------------------
      # Caddy — HTTPS reverse proxy with automatic TLS
      # ---------------------------------------------------------------------------
      caddy:
        image: caddy:2-alpine
        ports:
          - "80:80"
          - "443:443"
        volumes:
          - ./docker/Caddyfile:/etc/caddy/Caddyfile:ro
          - caddy_data:/data
          - caddy_config:/config
        depends_on:
          superset:
            condition: service_started
        restart: unless-stopped
    ```

    2. On the `superset` service, REMOVE the `ports` key entirely (lines currently reading `ports: - "${SUPERSET_PORT:-8088}:8088"`). The superset container will still listen on 8088 inside the Docker network, but it will NOT be accessible from the host. Only Caddy (on ports 80/443) will be exposed. Add `expose: - "8088"` instead to document the internal port (optional but good practice).

    3. Add `caddy_data` and `caddy_config` to the top-level `volumes:` section at the bottom of the file:

    ```yaml
    volumes:
      postgres_data:
      redis_data:
      superset_home:
      caddy_data:
      caddy_config:
    ```

    This addresses SEC-01 (HTTPS via Caddy), SEC-05 (port 8088 not exposed externally).

<task type="auto">
  <name>Task 2: Enable Talisman, secure cookies, and verify SECRET_KEY documentation</name>
  <files>docker/superset_config.py</files>
  <action>
    **Modify `docker/superset_config.py`** in the "Security & Production Hardening" section (starting at line 92):

    Replace:
    ```python
    WTF_CSRF_ENABLED = True
    SESSION_COOKIE_HTTPONLY = True
    SESSION_COOKIE_SAMESITE = "Lax"
    TALISMAN_ENABLED = False  # enable when behind HTTPS reverse proxy
    ```

    With:
    ```python
    WTF_CSRF_ENABLED = True
    SESSION_COOKIE_HTTPONLY = True
    SESSION_COOKIE_SECURE = True
    SESSION_COOKIE_SAMESITE = "Strict"
    TALISMAN_ENABLED = True
    TALISMAN_CONFIG = {
        "force_https": True,
        "session_cookie_secure": True,
        "content_security_policy": {
            "default-src": ["'self'"],
            "img-src": ["'self'", "data:", "blob:"],
            "script-src": ["'self'", "'unsafe-inline'", "'unsafe-eval'"],
            "style-src": ["'self'", "'unsafe-inline'"],
            "worker-src": ["'self'", "blob:"],
            "connect-src": ["'self'"],
            "object-src": ["'none'"],
            "base-uri": ["'self'"],
        },
    }
    ```

    Notes on the CSP:
    - `unsafe-inline` and `unsafe-eval` in script-src are required because Superset's frontend uses inline scripts and eval (React-based SPA). Without these, the UI breaks. This is the standard Superset CSP configuration.
    - `blob:` in img-src and worker-src is required for chart rendering (ECharts exports).
    - `data:` in img-src is needed for Superset's embedded base64 images.

    This addresses SEC-03 (SESSION_COOKIE_SECURE + HTTPONLY), SEC-04 (Talisman CSP headers).

    **Verify SECRET_KEY documentation (SEC-02):** The SECRET_KEY is already read from the environment (`os.environ["SUPERSET_SECRET_KEY"]` on line 13). No code change needed. Add a comment above line 13:

    ```python
    # Never rotate after first deployment — it encrypts saved database credentials.

    ```
