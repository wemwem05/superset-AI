# Codebase Structure

**Analysis Date:** 2026-03-26

## Directory Layout

```
superset/
├── docker/                  # Docker configuration and initialization
│   ├── superset_config.py   # Apache Superset settings (database, cache, Celery, security)
│   └── superset-init.sh     # One-shot initialization script (migrations + admin user)
├── docker-compose.yml       # Orchestration: defines all services, volumes, dependencies, health checks
├── Dockerfile               # Custom image build (adds psycopg2 PostgreSQL driver)
├── .env                     # Environment variables (secrets, DB credentials, feature toggles) — gitignored
├── .env.example             # Template for .env with documented variables
├── README.md                # User guide (quick start, operations, production checklist)
├── CLAUDE.md                # Project documentation (architecture, productionization recommendations)
└── .planning/               # GSD planning artifacts (generated)
    └── codebase/            # Codebase analysis documents
```

## Directory Purposes

**docker/ Directory:**
- Purpose: Container runtime configuration and startup orchestration
- Contains: Superset Python config file, shell initialization script
- Key files: `superset_config.py` (runtime settings), `superset-init.sh` (bootstrap commands)

**Root Directory:**
- Purpose: Deployment configuration and documentation
- Contains: Docker Compose manifest, custom Dockerfile, environment config, guides
- Key files: `docker-compose.yml` (service definitions), `.env` (runtime secrets), `README.md` (operations guide)

**.planning/codebase/ Directory:**
- Purpose: GSD codebase mapping artifacts (generated by `/gsd:map-codebase` command)
- Contains: Architecture analysis, structure documentation, testing patterns, conventions
- Key files: Generated markdown documents (ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, etc.)

## Key File Locations

**Entry Points:**
- `docker-compose.yml`: Primary orchestration file; lists all services and their configurations
- `./docker/superset-init.sh`: Bootstrap script executed once per deployment; runs migrations and admin setup
- `Dockerfile`: Custom image build; installs PostgreSQL driver on top of apache/superset:4.1.1

**Configuration:**
- `docker/superset_config.py`: Superset application settings (database connection, cache, Celery, security, feature flags)
- `.env`: Runtime environment variables (secrets, credentials, feature toggles, ports)
- `.env.example`: Template documenting all required environment variables

**Core Logic:**
- Apache Superset application code: Shipped in `apache/superset:4.1.1` Docker image; not directly editable in this repo
- Customizations: Limited to `docker/superset_config.py` (configuration) and `Dockerfile` (dependencies)

**Documentation:**
- `README.md`: Quick start, operations guide, dashboard building workflow, production checklist
- `CLAUDE.md`: Architecture overview, productionization recommendations, key commands
- `.planning/codebase/`: GSD analysis documents (architecture, testing, conventions, concerns)

## Naming Conventions

**Files:**
- UPPERCASE.md: Documentation files (README, CLAUDE) and GSD artifacts (ARCHITECTURE.md, STRUCTURE.md)
- lowercase_with_underscores.py: Python configuration files (superset_config.py)
- lowercase-with-hyphens.sh: Shell scripts (superset-init.sh)
- docker-compose.yml: Docker Compose manifest (standard convention)
- Dockerfile: Custom Docker image definition (standard convention)

**Directories:**
- lowercase: Standard directories (docker, .planning, .env.example naming)
- dot-prefixed: Hidden/special directories (.planning, .idea, .claude, .git, .venv)

## Where to Add New Code

**New Feature/Customization:**
- Configuration changes: `./docker/superset_config.py` (add to FEATURE_FLAGS, CACHE_CONFIG, or CeleryConfig)
- Initialization logic: `./docker/superset-init.sh` (if one-time setup needed)
- Environment variables: `.env` and `.env.example` (add new VAR=value pairs with documentation)
- Custom Dockerfile steps: `./Dockerfile` (e.g., installing additional database drivers)

**New Service/Dependency:**
- Service definition: Add new service block in `docker-compose.yml` with image, ports, volumes, environment, depends_on
- Configuration: Reference new service in `docker/superset_config.py` (e.g., if adding external cache or queue)
- Documentation: Update `README.md` (service table, setup steps) and `.env.example` (new env vars)

**Documentation:**
- User guides: `README.md` (operations, building dashboards, troubleshooting)
- Architecture/design: `CLAUDE.md` (productionization guidance, patterns)
- GSD artifacts: `.planning/codebase/*.md` (generated by mapping commands)

## Docker Service Entry Points

**superset-init:**
- Runs once before other services start
- Location: `docker-compose.yml` lines 50-58
- Command: `/bin/bash /app/superset-init.sh` → executes `./docker/superset-init.sh`
- Exit behavior: Restarts disabled (`restart: no`); other services wait for success

**superset (web server):**
- Main HTTP server
- Location: `docker-compose.yml` lines 63-75
- Command: Gunicorn with 4 workers, 120s timeout
- Exposed port: 8088 (configurable via SUPERSET_PORT env var)
- Start condition: Waits for superset-init success + postgres/redis health

**superset-worker (Celery worker):**
- Async task processor
- Location: `docker-compose.yml` lines 80-90
- Command: Celery worker with prefork pool, 2 concurrency, 128 max tasks per child
- Log level: WARNING
- Start condition: Waits for superset-init success + postgres/redis health

**superset-beat (Celery scheduler):**
- Periodic task scheduler
- Location: `docker-compose.yml` lines 95-105
- Command: Celery beat with schedule at /tmp/celerybeat-schedule
- Log level: WARNING
- Start condition: Waits for superset-init success + postgres/redis health

**postgres (PostgreSQL):**
- Metadata database
- Location: `docker-compose.yml` lines 21-31
- Image: postgres:16-alpine
- Volume: postgres_data (persistent)
- Health check: pg_isready command

**redis (Redis):**
- Cache + Celery broker
- Location: `docker-compose.yml` lines 36-45
- Image: redis:7-alpine
- Volume: redis_data (persistent)
- Health check: redis-cli ping

## Environment Variables Reference

**Required (must set in .env before first deployment):**
- `SUPERSET_SECRET_KEY`: Long random string (e.g., `openssl rand -base64 42`); encrypts saved credentials
- `SUPERSET_ADMIN_PASSWORD`: Admin account password
- `POSTGRES_PASSWORD`: PostgreSQL password

**Superset Configuration:**
- `SUPERSET_ADMIN_USERNAME`: Admin username (default: admin)
- `SUPERSET_ADMIN_FIRSTNAME`: Admin first name
- `SUPERSET_ADMIN_LASTNAME`: Admin last name
- `SUPERSET_ADMIN_EMAIL`: Admin email address
- `SUPERSET_LOAD_EXAMPLES`: Load example datasets on init (yes/no)
- `SUPERSET_PORT`: HTTP port (default: 8088)

**Database (PostgreSQL):**
- `POSTGRES_USER`: DB user (default: superset)
- `POSTGRES_DB`: DB name (default: superset)
- `DATABASE_HOST`: DB hostname (default: postgres, Docker service name)
- `DATABASE_PORT`: DB port (default: 5432)

**Cache & Broker (Redis):**
- `REDIS_HOST`: Redis hostname (default: redis, Docker service name)
- `REDIS_PORT`: Redis port (default: 6379)

**Optional:**
- `MAPBOX_API_KEY`: Mapbox token for map visualizations (empty string disables)
